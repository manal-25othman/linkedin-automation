# أنجز — منصّة خدمات إلكترونية ببرنامج تسويق بالعمولة

منصّة عربية (RTL) تبيع خدمات إلكترونية بباقات وأسعار واضحة — على غرار منصّات الخدمات
العامة مثل «أزهل» — ومعها **برنامج تسويق بالعمولة كامل** مبنيّ داخل المنتج لا مضافًا
عليه: روابط إحالة، أكواد خصم، احتساب عمولة، مستويات، ومحفظة سحوبات.

```
زائر ──/r/CODE──▶ كوكي إحالة (٣٠ يومًا) ──▶ طلب ──▶ دفع ──▶ عمولة معلّقة
                                                              │
                          اكتمال الخدمة ──▶ مدّة تثبيت ──▶ عمولة معتمدة ──▶ سحب بنكي
```

## ما الذي يعمل فعلًا

| المساحة | التفاصيل |
|---|---|
| **المتجر** | رئيسية، دليل خدمات ببحث وتصنيفات، صفحة خدمة بثلاث باقات، نموذج طلب، دفع، صفحة تتبّع الطلب برقمه |
| **الطلبات** | رقم طلب فريد، مفتاح متابعة سرّي، سجلّ حالات لا يُعدَّل، انتقالات حالة محكومة بقواعد |
| **الدفع** | مزوّد تجريبي للتطوير + تكامل ميسر (Moyasar) + Webhook يتحمّل التكرار (idempotent) |
| **الإحالة** | رابط `/r/CODE`، أو `?ref=CODE` على أي صفحة، تسجيل نقرات، نافذة نسب قابلة للضبط |
| **العمولات** | نسبة عامة/لكل خدمة/تفاوضية، مكافأة مستوى، مدّة تثبيت، إلغاء تلقائي عند الاسترجاع |
| **لوحة الشريك** | إحصاءات، مولّد روابط، أكواد خصمه، عمولاته، طلب سحب، بيانات التحويل |
| **لوحة الإدارة** | مؤشّرات، طلبات، خدمات وباقات، تصنيفات، اعتماد المسوّقين، مراجعة العمولات، صرف السحوبات، أكواد خصم، إعدادات البرنامج |

## الهوية البصرية

| العنصر | القيمة |
|---|---|
| الخلفية | `#fffbf5` كريمي دافئ (لا أبيض رمادي) |
| اللون الأساسي | `#0e7c7b` تركوازي |
| لون الإشارة | `#ff6b4a` برتقالي مرجاني — للعمولة والأرباح ونداءات الفعل الثانوية |
| النص | `#10312f` أخضر مسودّ دافئ |
| الخط | Tajawal بأوزان ٤٠٠/٥٠٠/٧٠٠/٨٠٠ للعناوين والنصّ معًا |
| الحواف | بطاقات `1.25rem`، حقول `1rem`، أزرار كبسولة |
| الظلال | ملوّنة بالتركوازي لا رمادية — الظلّ الرمادي يجعل اللوحة الدافئة تبدو متّسخة |

كل القيم رموز CSS في `src/app/globals.css` تحت `@theme`: تغيير اللون الأساسي سطرٌ
واحد ينعكس على الموقع واللوحتين معًا. الشعار مكوّن SVG سطري في
`src/components/layout/logo.tsx` وله نسخة للخلفيات الداكنة.

## التقنيات

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS v4 · Prisma + PostgreSQL ·
جلسات على الخادم (bcrypt + HMAC) · Vitest.

## التشغيل محليًا

```bash
cd anjez
npm install
cp .env.example .env          # ثم املأ القيم
npx prisma migrate deploy     # أو: npm run db:migrate
npm run db:seed               # كتالوج عربي + حساب أدمن + مسوّق تجريبي
npm run dev
```

بيانات الدخول بعد البذور في التطوير:

- الإدارة: `admin@anjez.local` / `Anjez12345` → `/admin/login`
- مسوّق تجريبي: `partner@anjez.local` / `Partner12345` (الكود `ANJEZ1`) → `/partner/login`

> غيّر كلمتَي المرور فورًا، واضبط `SEED_ADMIN_PASSWORD` قبل أي بذر في الإنتاج.

### متغيّرات البيئة

| المتغيّر | الغرض |
|---|---|
| `DATABASE_URL` | اتصال التطبيق (على Vercel استخدم رابط الـ pooler) |
| `DIRECT_URL` | اتصال مباشر للهجرات فقط (محليًا = نفس القيمة) |
| `AUTH_SECRET` | توقيع الجلسات — `openssl rand -base64 48` |
| `NEXT_PUBLIC_SITE_URL` | العنوان العام (روابط الإحالة والعودة من الدفع) |
| `PAYMENT_PROVIDER` | `mock` أو `moyasar` |
| `MOYASAR_SECRET_KEY` / `MOYASAR_WEBHOOK_SECRET` | مفاتيح بوّابة الدفع |
| `ALLOW_MOCK_PAYMENTS` | يفتح صفحة الدفع التجريبية في الإنتاج — اتركه فارغًا |
| `CRON_SECRET` | تصريح مهمّة اعتماد العمولات |

## كيف تُحسب العمولة

الملفّ المرجعي: `src/lib/affiliate/commission.ts` (دوال نقية، مغطّاة باختبارات).

1. **النسبة**: نسبة المسوّق التفاوضية إن وُجدت — وإلا نسبة الخدمة أو النسبة العامة،
   مضافًا إليها مكافأة المستوى، ومحصورة بسقف صلب (٥٠٪ افتراضيًا).
2. **الوعاء**: ما دفعه العميل فعلًا بعد الخصم — لا السعر المعلن.
3. **التقريب**: لأسفل دائمًا، وكل المبالغ أعداد صحيحة بالهللات (لا عشريات عائمة).
4. **النسب**: الكوبون يسبق الكوكي — كتابة الكود فعل صريح، والكوكي أثر سابق.
5. **الحياة**: `PENDING` عند الدفع → `APPROVED` بعد اكتمال الطلب ومرور مدّة التثبيت
   (١٤ يومًا افتراضيًا) → `PAID` عند صرف السحب. الإلغاء أو الاسترجاع يُلغيها ما لم تُصرف.
6. **المستويات**: برونزي → فضّي → ذهبي حسب مجموع المبيعات المعتمدة، وتُرقّى تلقائيًا.

كل هذه القيم تُعدَّل من `/admin/settings` بلا إعادة نشر، وتسري على الطلبات اللاحقة فقط:
الطلب القائم يحمل نسبته مقفلةً عليه.

## النشر

دليل مفصّل خطوة بخطوة: [`DEPLOY.md`](DEPLOY.md). باختصار:

1. **قاعدة البيانات**: Neon أو Supabase أو أي PostgreSQL. اضبط `DATABASE_URL` على الـ pooler
   و`DIRECT_URL` على الاتصال المباشر.
2. **Vercel**: أمر البناء `npm run vercel-build` (يشغّل الهجرات ثم البناء).
3. **الدفع**: `PAYMENT_PROVIDER=manual` للتحويل البنكي (العميل يحوّل، والإدارة تؤكّد
   الاستلام من صفحة الطلب فتُحتسب العمولة) — مناسب للتشغيل قبل اعتماد بوّابة.
   ولتفعيل الدفع الإلكتروني: `PAYMENT_PROVIDER=moyasar`، وأضف المفاتيح، واضبط Webhook على
   `https://<نطاقك>/api/payments/webhook` بنفس قيمة `MOYASAR_WEBHOOK_SECRET`.
4. **مهمّة مجدولة** (اختيارية): استدعِ `GET /api/cron/commissions` يوميًا بترويسة
   `Authorization: Bearer $CRON_SECRET`. اللوحة تعتمد المستحقّ عند فتحها أيضًا،
   فتعطّل المهمّة يؤخّر الاعتماد ولا يُسقطه.

## ملاحظات أمنية مقصودة

- الجلسة كوكي `httpOnly` تحمل سرًّا خامًا، والقاعدة تحفظ HMAC له فقط.
- صفحة الطلب لا تُفتح برقم الطلب وحده: يلزم مفتاح متابعة سرّي، وتتبّع الطلب يطابق الجوال.
- حدود معدّل على الدخول والتسجيل والطلب والتتبّع، وعناوين الاتصال تُخزَّن مهشَّمة.
- `/r/CODE` يقبل الوجهات الداخلية فقط، فلا يصلح جسرًا لإعادة توجيه مفتوح.
- صفحة الدفع التجريبية مغلقة في الإنتاج ما لم تُفتح صراحةً.

## ما لم يُبنَ بعد

- إشعارات بريد/واتساب عند تغيّر حالة الطلب أو اعتماد العمولة.
- رفع ملفّات العميل داخل الطلب (المتطلبات تُرسل حاليًا عبر قناة التواصل).
- تقارير تفصيلية للمسوّق (أداء حسب الخدمة والمصدر).
- حدّ معدّل مشترك بين النسخ (المخزن الحالي في الذاكرة يكفي لخادم واحد).
