# نشر استدلال على الإنترنت

الموقع الآن كود في GitHub فقط. هذا الدليل ينقله إلى نطاق يفتحه الناس.

**الترتيب المُوصى به:** انشر على نطاق مؤقّت مجاني أولًا (١٠ دقائق) → جرّب كل شيء → اربط نطاقك → قدّم لأدسنس بعد شهور.

---

## قبل أن تبدأ

```bash
cd istidlal
npm run prelaunch
```

يطبع قائمة بما ينقص. **الموانع** تُصلَح قبل النشر، و**التنبيهات** قرارات تختارينها.

---

## الخطوة ١ — الاستضافة (Vercel)

Vercel من صانعي Next.js، وخطتها المجانية تكفي مدونة تمامًا: بناء تلقائي عند كل دفعة، وشهادة SSL، وشبكة توصيل عالمية.

1. ادخل [vercel.com](https://vercel.com) وسجّل **بحساب GitHub**.
2. **Add New → Project**، واختر مستودع `linkedin-automation`.
3. **الإعداد الحاسم:** المستودع يضمّ أكثر من مشروع، فاضبط:

   | الحقل | القيمة |
   |---|---|
   | **Root Directory** | `istidlal` ← **لا تتخطّى هذا** |
   | Framework Preset | Next.js (يُكتشف تلقائيًّا) |
   | Build Command | `npm run build` (الافتراضي) |

4. **Environment Variables** — أضف قبل أول بناء:

   ```
   NEXT_PUBLIC_SITE_URL = https://<اسم-مشروعك>.vercel.app
   ```

   > الرابط الأساسي وخريطة الموقع وصور المشاركة تُبنى منه. غيّره لاحقًا إلى نطاقك.

5. **Deploy**. بعد دقيقتين يصبح الموقع على `https://<اسم-مشروعك>.vercel.app`.

### فرع النشر

Vercel ينشر من الفرع الرئيسي (`main`). العمل الحالي على `claude/ai-blog-launch-plan-cwvgjg`، فادمجه أولًا:

- من GitHub: افتح **Pull Request** من فرع العمل إلى `main`، راجع التغييرات، ثم **Merge**.
- أو اختر فرع العمل نفسه فرعَ إنتاج في `Settings → Git → Production Branch`.

كل دفعة إلى فرع الإنتاج تُطلق بناءً جديدًا. وكل طلب دمج يحصل على رابط معاينة مستقلّ.

## الخطوة ٢ — النطاق

### تسجيل النطاق

| النطاق | الكلفة التقريبية سنويًّا | ملاحظة |
|---|---|---|
| `istidlal.ai` | ٧٠–١٠٠ $ | الامتداد يقول التخصص |
| `istidlal.com` | ١٠–١٥ $ | الأوسع تعرّفًا |
| `istidlal.dev` | ١٢–٢٠ $ | تقني، وHTTPS إلزامي فيه |

المسجّلون المعتادون: Cloudflare Registrar (بسعر التكلفة)، Namecheap، Porkbun. **تحقّق من توفّر الاسم أولًا** — `istidlal.ai` مجرّد اقتراح في الخطة ولم يُحجز.

### الربط بـVercel

1. في Vercel: `Settings → Domains → Add`، وأدخل نطاقك.
2. Vercel يعطيك سجلّات DNS. عند مسجّل النطاق أضف:

   | النوع | الاسم | القيمة |
   |---|---|---|
   | A | `@` | `76.76.21.21` |
   | CNAME | `www` | `cname.vercel-dns.com` |

   > القيم الدقيقة تظهر في لوحة Vercel — انسخها منها لا من هنا.

3. انتظر انتشار DNS (دقائق إلى ساعات)، وستصدر شهادة SSL تلقائيًّا.
4. **حدّث متغيّر البيئة**: `NEXT_PUBLIC_SITE_URL = https://نطاقك` ثم أعد النشر (`Deployments → ⋯ → Redeploy`) — بدون ذلك تبقى خريطة الموقع تشير إلى العنوان القديم.

### البريد

النطاق لا يعطيك بريدًا. لتشغيل `hello@نطاقك`: Zoho Mail (مجاني لمستخدم واحد)، أو Google Workspace، أو تحويل بسيط من Cloudflare Email Routing. ثم **حدّث العناوين في `src/config/site.ts`** — بريد يعمل شرطٌ في مراجعة أدسنس.

## الخطوة ٣ — بعد أول نشر

### تحقّق يدوي

- [ ] الصفحة الرئيسية والمقالات وصفحات السياسات تفتح.
- [ ] `‎/sitemap.xml` يعرض نطاقك الجديد لا الافتراضي.
- [ ] `‎/robots.txt` سليم، و`‎/admin` محجوب عن الفهرسة.
- [ ] لافتة الكوكيز تظهر، و«الضروري فقط» يعمل.
- [ ] الوضع الداكن والبحث الداخلي يعملان على الجوال.
- [ ] شارك رابط مقال في واتساب أو لينكدإن — يجب أن تظهر صورة المشاركة.

### Search Console

1. [search.google.com/search-console](https://search.google.com/search-console) → **إضافة موقع** → *بادئة عنوان URL* بنطاقك.
2. تحقّق بالملكية (Vercel يسهّل التحقّق بسجلّ DNS).
3. **أرسل خريطة الموقع**: `https://نطاقك/sitemap.xml`.
4. اطلب فهرسة الصفحة الرئيسية ومقالات الركيزة.

### GA4

أنشئ خاصية في [analytics.google.com](https://analytics.google.com)، وخذ المعرّف `G-XXXXXXX`، وأضفه متغيّر بيئة `NEXT_PUBLIC_GA4_ID`، ثم أعد النشر. لن يُحمَّل السكربت إلا بعد موافقة الزائر على الكوكيز التحليلية.

### أدسنس — لاحقًا لا الآن

لا تقدّم قبل ٢٥–٣٠ مقالًا وثلاثة أشهر عمر نطاق وحركة عضوية مستقرّة. القائمة الكاملة في [`ADSENSE.md`](./ADSENSE.md).

## بدائل الاستضافة

| المنصّة | ملاحظة |
|---|---|
| **Cloudflare Pages** | مجانية بسخاء؛ Next.js يحتاج محوّل `@cloudflare/next-on-pages` وبعض الضبط |
| **Netlify** | قريبة من Vercel؛ تحتاج إضافة Next.js الرسمية |
| **خادم خاص (VPS)** | `npm run build && npm start` خلف Nginx — تحكّم كامل مقابل صيانة دائمة |

لمشروع Next.js بهذا الحجم، Vercel أقلّها احتكاكًا.

## استكشاف الأعطال

| العَرَض | السبب الغالب |
|---|---|
| البناء يفشل: `No Next.js version detected` | **Root Directory** ليس `istidlal` |
| الروابط وخريطة الموقع تشير إلى `istidlal.ai` | `NEXT_PUBLIC_SITE_URL` غير مضبوط أو لم يُعد النشر بعد تغييره |
| صور المشاركة لا تظهر | نفس السبب أعلاه — تُبنى من الرابط الأساسي |
| الخطوط لا تُحمَّل | البناء لم يصل إلى Google Fonts؛ أعد النشر |
| `‎/admin` صفحة فارغة | حزمة المحرّر لم تُنسَخ — تأكّد أن البناء نفّذ `prebuild` |
