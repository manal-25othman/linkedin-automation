# نقل المشروع إلى مستودع مستقلّ

استدلال اليوم داخل مستودع `linkedin-automation` مع مشروعين آخرين. نقله إلى مستودع باسمه **يستغرق دقيقتين ويحفظ تاريخ الكوميتات**، ويكسب ثلاثة أشياء:

- **جذر نظيف**: لا حاجة لضبط Root Directory في Vercel، ولا بادئة `istidlal/` في مسارات المحرّر.
- **صلاحيات أضيق**: من يحرّر المدونة لا يرى أتمتة لينكدإن ولا المشاريع الأخرى.
- **اسم يدلّ عليه**: رابط المستودع جزء من هوية المشروع.

## التنفيذ — أمر واحد

من جذر المستودع الحالي:

```bash
bash istidlal/scripts/extract-standalone.sh ../istidlal-site
```

يفعل الأمر ثلاثة أشياء:

1. يستخرج تاريخ مجلّد `istidlal` كاملًا (`git subtree split`) — الكوميتات تنتقل معه، لا لقطة واحدة.
2. ينشئ مستودعًا في `../istidlal-site` بفرع `main` وبالمشروع في جذره.
3. ينسخ `.pages.yml` إلى الجذر بعد حذف بادئة `istidlal/` من كل مسار.

ثم:

```bash
# أنشئ مستودعًا فارغًا على GitHub (بلا README ولا .gitignore)
cd ../istidlal-site
git remote add origin git@github.com:<اسمك>/<المستودع>.git
git push -u origin main
```

## ما يجب تعديله بعد النقل

| الملف | التعديل |
|---|---|
| `.pages.yml` | تمّ آليًّا (المسارات بلا بادئة) |
| `public/admin/config.yml` | غيّر `repo:` إلى `<اسمك>/<المستودع>` |
| Vercel | **Root Directory = `.`** بدل `istidlal` |
| Pages CMS | امنح التطبيق صلاحية على المستودع الجديد |
| `docs/*` | حدّث اسم المستودع حيثما ذُكر |

## هل يُحذف المستودع القديم؟

لا داعي. اترك نسخة استدلال فيه كما هي أو احذف المجلّد بكوميت — التاريخ محفوظ في المستودع الجديد بأي حال. أتمتة لينكدإن تبقى حيث هي وتُستعمل قناةَ توزيعٍ للمدونة.

## التحقّق

الأمر مُجرَّب من هذه الجلسة: المستودع المستخرَج ثبّت الاعتمادات وبنى ٩٥ صفحة واجتاز فحص المحتوى — بلا تعديل يدوي واحد.
