# محرّر المحتوى — دليل التشغيل

المحرّر لوحة على `‎/admin` تحرّر ملفات المحتوى في المستودع مباشرةً: كل حفظ يصبح كوميت في GitHub، وكل كوميت يُطلق بناءً جديدًا للموقع. **لا قاعدة بيانات، ولا خادم إدارة، ولا نسخة ثانية من المحتوى.**

## ماذا يحرّر

| المجموعة | الملفات | يستطيع |
|---|---|---|
| المقالات | `content/articles/*.md` | إنشاء وتعديل وحذف |
| الصفحات | `content/pages/*.md` | تعديل فقط (لا إنشاء ولا حذف — مسارات ثابتة مرتبطة بالكود) |

الحقول معرَّفة في `public/admin/config.yml` بأسماء عربية، ومع تلميحات تفرض قواعد سياسة التحرير: طول الوصف، وثلاث نقاط خلاصة على الأقل، وتذكير بقسمَي «الأسئلة الشائعة» و«المراجع».

## التفعيل — ثلاث خطوات

### ١) أنشئ تطبيق OAuth في GitHub
`Settings → Developer settings → OAuth Apps → New OAuth App`

| الحقل | القيمة |
|---|---|
| Application name | `محرّر استدلال` |
| Homepage URL | `https://istidlal.ai` |
| Authorization callback URL | `https://istidlal.ai/api/oauth/callback` |

احفظ `Client ID`، وأنشئ `Client Secret` واحفظه فور ظهوره.

### ٢) اضبط متغيّرَي البيئة في الاستضافة

```
GITHUB_OAUTH_ID=...
GITHUB_OAUTH_SECRET=...
```

**لا تضعهما في ملف داخل المستودع** — هما سرّان، ويُضبطان في لوحة الاستضافة. قبل ضبطهما يردّ `‎/api/oauth/github` برسالة «المحرّر غير مُفعَّل»، ولا تفتح اللوحة.

### ٣) صحّح إعدادات المستودع في `public/admin/config.yml`

```yaml
backend:
  repo: manal-25othman/linkedin-automation   # المستودع الصحيح
  branch: main                               # الفرع الذي ينشر منه الموقع
  base_url: https://istidlal.ai              # نطاقك بعد التسجيل
```

## كيف يعمل الاستيثاق

نقطتا الاستيثاق مبنيّتان داخل الموقع (`src/app/api/oauth/`)، فلا يمرّ رمز الوصول بوسيط خارجي:

1. المحرّر يفتح نافذة على `‎/api/oauth/github`.
2. النقطة تحوّلك إلى GitHub لتأذن للتطبيق.
3. GitHub يعيدك إلى `‎/api/oauth/callback` برمز مؤقّت.
4. الخادم يبدّل الرمز المؤقّت برمز وصول، ويسلّمه لنافذة المحرّر عبر `postMessage`.

الصلاحية المطلوبة `repo` لأن المحرّر يكتب ملفات في المستودع. من يملك الإذن على المستودع يستطيع الدخول — تُدار الصلاحيات من GitHub نفسه، لا من الموقع.

## سير العمل التحريري

`publish_mode: editorial_workflow` مفعّل، فالمقال يمرّ بثلاث حالات:

**مسودّة** ← **قيد المراجعة** ← **جاهز للنشر**

كل مسودّة تصبح فرعًا وطلب دمج على GitHub. الضغط على «نشر» يدمج الطلب في الفرع الرئيسي، فيُطلق بناء الموقع.

## قبل النشر — تحقّق محلّي

```bash
npm run check:content   # يفرض قواعد سياسة التحرير على كل مقال
npm run build           # يكشف أي كسر في البناء
```

يُستحسن ربط `check:content` بفحص آلي على طلبات الدمج، فلا يُدمج مقال ينقصه قسم المراجع أو الأسئلة الشائعة.

## حدود معروفة

- **صفحتا `/newsletter` و`/search`** ليستا في المحرّر: الأولى نموذج اشتراك والثانية أداة بحث، ومحتواهما في الكود.
- **إنشاء صفحة جديدة** يحتاج إضافة مسار في الكود أيضًا؛ لذلك مجموعة الصفحات للتعديل فقط.
- **الصور**: ترفع إلى `public/uploads` وتُدرَج بمسار `/uploads/...`. أغلفة المقالات تُولَّد آليًّا ولا تُرفع.
- **المعاينة داخل المحرّر** تعرض Markdown خامًّا لا تصميم الموقع؛ المعاينة الحقيقية من رابط البناء بعد الحفظ.
