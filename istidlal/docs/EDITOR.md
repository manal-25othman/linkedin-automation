# محرّر المحتوى — دليل التشغيل

المحرّر لوحة على `‎/admin` تحرّر ملفات المحتوى مباشرةً: كل حفظ يصبح كوميت في المستودع، وكل كوميت يُطلق بناءً جديدًا للموقع. **لا قاعدة بيانات، ولا خادم إدارة، ولا نسخة ثانية من المحتوى.**

الحزمة مستضافة مع الموقع (تُنسخ من `node_modules` عند كل بناء عبر `scripts/sync-cms.mjs`)، فلا يعتمد التحرير على توفّر شبكة توصيل خارجية.

## ماذا يحرّر

| المجموعة | الملفات | يستطيع |
|---|---|---|
| المقالات | `content/articles/*.md` | إنشاء وتعديل وحذف |
| الصفحات | `content/pages/*.md` | تعديل فقط (لا إنشاء ولا حذف — مساراتها مرتبطة بالكود) |

الحقول معرَّفة في `public/admin/config.yml` بأسماء عربية، وتفرض قواعد سياسة التحرير داخل النموذج: طول الوصف، وثلاث نقاط خلاصة على الأقل، وتصنيف من قائمة مغلقة، وتذكير بقسمَي «الأسئلة الشائعة» و«المراجع».

## ثلاث طرق للدخول

### ١) العمل على مستودع محلي — يعمل الآن، بلا تسجيل دخول

```bash
npm install
npm run dev     # ينسخ حزمة المحرّر تلقائيًّا ثم يشغّل الخادم
```

افتح `http://localhost:3000/admin` واضغط **Work with Local Repository**، ثم اختر مجلّد المستودع. يحرّر المحرّر الملفات على قرصك مباشرةً، وتراجع التغييرات بـ`git diff` وتدفعها بنفسك.

- يحتاج متصفّحًا يدعم File System Access API: **Chrome أو Edge** (لا يعمل في Firefox أو Safari).
- لا يحتاج إنترنت ولا نطاقًا ولا استيثاقًا.
- **الأنسب للبدء اليوم.**

### ٢) رمز وصول شخصي — يحفظ في GitHub، بلا نطاق

أنشئ رمزًا من GitHub: `Settings → Developer settings → Personal access tokens`، بصلاحية **`repo`**، ثم اضغط **Sign In Using Access Token** وألصقه.

- كل حفظ كوميت مباشر في المستودع، حتى وأنت تعمل على `localhost`.
- الرمز يُحفظ في متصفّحك وحده. **لا تلصقه في أي ملف داخل المستودع.**
- امنحه أقصر مدة صلاحية تكفيك، وأبطله فور انتهاء الحاجة.

### ٣) الدخول بضغطة واحدة (OAuth) — بعد نشر الموقع على نطاقك

**أ. أنشئ تطبيق OAuth في GitHub**
`Settings → Developer settings → OAuth Apps → New OAuth App`

| الحقل | القيمة |
|---|---|
| Application name | `محرّر استدلال` |
| Homepage URL | `https://istidlal.ai` |
| Authorization callback URL | `https://istidlal.ai/api/oauth/callback` |

**ب. اضبط متغيّرَي البيئة في الاستضافة**

```
GITHUB_OAUTH_ID=...
GITHUB_OAUTH_SECRET=...
```

سرّان، يُضبطان في لوحة الاستضافة لا في المستودع. قبل ضبطهما يردّ `‎/api/oauth/github` برسالة «المحرّر غير مُفعَّل».

**ج. صحّح `public/admin/config.yml`**

```yaml
backend:
  repo: manal-25othman/linkedin-automation   # المستودع
  branch: main                               # الفرع الذي ينشر منه الموقع
  base_url: https://istidlal.ai              # نطاقك بعد التسجيل
```

نقطتا الاستيثاق مبنيّتان داخل الموقع (`src/app/api/oauth/`)، فلا يمرّ رمز الوصول بوسيط خارجي. من يملك إذن الكتابة على المستودع يستطيع الدخول — الصلاحيات تُدار من GitHub، لا من الموقع.

## سير العمل التحريري

`publish_mode: editorial_workflow` مفعّل مع طريقتَي GitHub (٢ و٣)، فالمقال يمرّ بثلاث حالات:

**مسودّة** ← **قيد المراجعة** ← **جاهز للنشر**

كل مسودّة تصبح فرعًا وطلب دمج على GitHub، والضغط على «نشر» يدمجها فيُطلق بناء الموقع. في وضع المستودع المحلي (طريقة ١) لا تنطبق هذه الحالات: التغيير يُكتب على القرص وأنت من يديره بـgit.

## قبل النشر — تحقّق محلّي

```bash
npm run check:content   # يفرض قواعد سياسة التحرير على كل مقال
npm run build           # يكشف أي كسر في البناء
```

يُستحسن ربط `check:content` بفحص آلي على طلبات الدمج، فلا يُدمج مقال ينقصه قسم المراجع أو الأسئلة الشائعة.

## حدود معروفة

- **واجهة المحرّر بالإنجليزية**: لا ترجمة عربية له بعد. حقول المقالات والصفحات عربية، ولوحة شرح عربية تظهر عند أول فتح لـ`‎/admin` وتُغلق بضغطة.
- **الأيقونات والخطوط** داخل المحرّر تُحمَّل من jsDelivr. تعمل عبر الإنترنت؛ وبلا اتصال تظهر الأيقونات كنصّ ويبقى المحرّر صالحًا للاستخدام.
- **صفحتا `/newsletter` و`/search`** خارج المحرّر: الأولى نموذج اشتراك والثانية أداة بحث، ومحتواهما في الكود.
- **إنشاء صفحة جديدة** يحتاج إضافة مسار في الكود أيضًا؛ لذلك مجموعة الصفحات للتعديل فقط.
- **الصور**: تُرفع إلى `public/uploads` وتُدرَج بمسار `/uploads/...`. أغلفة المقالات تُولَّد آليًّا ولا تُرفع.
- **المعاينة داخل المحرّر** تعرض Markdown لا تصميم الموقع؛ المعاينة الحقيقية من رابط البناء بعد الحفظ.
