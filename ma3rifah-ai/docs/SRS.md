# وثيقة متطلبات البرمجيات (SRS)

**المنتج:** معرفة AI — Ma3rifah AI
**الوصف:** منصة SaaS لإدارة المعرفة المؤسسية بالذكاء الاصطناعي، عربية أولًا
**الإصدار:** 1.0 — ما قبل الإطلاق التجاري
**التاريخ:** 2026-08-14 (محدَّثة بطبقة التحقق من المصادر)

> هذه الوثيقة تصف **النظام كما هو مبنيّ فعلًا**، لا كما نتمنّاه. كل رقم
> فيها مأخوذ من الكود أو من الهجرات. وما لم يُبنَ بعد مذكور صراحةً في
> القسم ١٠ «خارج النطاق الحالي» — لأن وثيقة تخلط المنجز بالمأمول تضلّل
> صاحبها قبل أن تضلّل غيره.

## ١. المقدمة

### ١.١ الغرض

تحديد المتطلبات الوظيفية وغير الوظيفية لمنصة «معرفة AI»، لتكون مرجعًا
للتطوير والاختبار والتفاوض مع العملاء والشركاء.

### ١.٢ نطاق المنتج

منصة سحابية متعددة المستأجرين (Multi-tenant SaaS) تمكّن الشركة من رفع
مستنداتها الداخلية، فتتحوّل تلقائيًا إلى قاعدة معرفة قابلة للسؤال
بالعربية. يسأل الموظف سؤالًا بلغته الطبيعية، فيجيبه مساعد ذكي بإجابة
**مستندة إلى وثائق شركته وحدها**، مع ذكر المصدر.

**المشكلة التي يحلّها:** المعرفة في الشركات السعودية محبوسة في ملفات
متناثرة وفي رؤوس الموظفين. الموظف الجديد يسأل زميله، والزميل مشغول،
والجواب يتأخر أو يأتي خاطئًا. وحين يستقيل موظف، تخرج معرفته معه.

### ١.٣ التعريفات

| المصطلح | المعنى |
|---|---|
| **المستأجر (Tenant)** | شركة عميلة. كل بياناتها معزولة عزلًا تامًا |
| **RAG** | الاسترجاع المعزّز بالتوليد: يبحث في وثائق الشركة ثم يجيب منها |
| **المقطع (Chunk)** | جزء من مستند بحجم مناسب للبحث الدلالي |
| **التضمين (Embedding)** | تمثيل رقمي للنص يتيح البحث بالمعنى لا بالكلمة |
| **RLS** | أمن مستوى الصف في PostgreSQL — حدّ العزل الفعلي |
| **فجوة معرفية** | سؤال لم تجب عنه قاعدة المعرفة، يدلّ على نقص في التوثيق |

### ١.٤ المراجع

- `docs/PHASE-12-SECURITY-VERIFICATION.md` — تقرير التحقق الأمني
- `supabase/migrations/` — مخطط قاعدة البيانات (١٢ هجرة)
- `tests/sql/` — اختبارات العزل بين المستأجرين

## ٢. الوصف العام

### ٢.١ منظور المنتج

منتج قائم بذاته، يُقدَّم عبر المتصفح باشتراك شهري. لا يتطلب تثبيتًا ولا
بنية تحتية لدى العميل.

### ٢.٢ فئات المستخدمين

| الدور | الوصف | الصلاحيات الجوهرية |
|---|---|---|
| **SUPER_ADMIN** | مالك المنصة | إدارة المنصة والشركات والخطط. لا يقرأ محتوى وثائق العملاء |
| **COMPANY_ADMIN** | مدير الشركة العميلة | إدارة الشركة والمستخدمين والأقسام والمستندات والتحليلات والفوترة |
| **MANAGER** | مدير قسم | عرض المستخدمين والأقسام، تحليلات قسمه، استخدام المساعد |
| **EMPLOYEE** | موظف | استخدام المساعد، عرض المستندات المصرّح له بها، محادثاته وحده |

### ٢.٣ بيئة التشغيل

| الطبقة | التقنية |
|---|---|
| الواجهة والخادم | Next.js 15 (App Router) + React 19 + TypeScript |
| التنسيق | Tailwind CSS + Radix UI — RTL أصلي |
| قاعدة البيانات | PostgreSQL (Supabase) + امتداد pgvector |
| المصادقة | Supabase Auth |
| التخزين | Supabase Storage |
| التوليد | Claude — `claude-opus-5` للمساعد، `claude-haiku-4-5` للمهام الخفيفة |
| التضمينات | Voyage AI — `voyage-3.5`، أبعاد ١٠٢٤ |
| الاستضافة | Vercel |

### ٢.٤ القيود

- **العربية أولًا:** الواجهة RTL بالكامل، والمعالجة النصية تراعي خصائص العربية
- **العزل مطلق:** لا مسار برمجي يسمح لشركة برؤية بيانات أخرى
- **بلا بيانات وهمية في الوظائف الجوهرية:** الإجابات من وثائق حقيقية أو لا إجابة

### ٢.٥ الافتراضات

- العميل يملك وثائق نصية (لا صورًا ممسوحة) — فالنظام لا يدعم OCR بعد
- اتصال إنترنت مستقر
- الشركة مستعدة لرفع وثائقها الداخلية إلى سحابة خارجية

## ٤. المتطلبات غير الوظيفية

### ٤.١ الأمن — أهم قسم في هذه الوثيقة

| الرقم | المتطلب | التنفيذ |
|---|---|---|
| NFR-1.1 | **عزل تام بين الشركات** | RLS على كل جدول، والتحقق في قاعدة البيانات لا في الواجهة |
| NFR-1.2 | التحقق من الصلاحية على الخادم | كل إجراء يمرّ بـ`requirePermission` قبل أي عملية |
| NFR-1.3 | تقييد المستند داخل الشركة | لا تتسرّب مقاطع مستند ممنوع إلى سياق RAG |
| NFR-1.4 | لا أسرار في المتصفح | مفاتيح الخدمة على الخادم وحده |
| NFR-1.5 | لا أسرار في Git | `.env.example` بلا قيم |
| NFR-1.6 | لا تسجيل لمحتوى حسّاس | لا كلمات مرور ولا مفاتيح ولا محتوى وثائق |
| NFR-1.7 | لا تسريب أثر التنفيذ للمستخدم | رسائل عربية مفهومة؛ التفاصيل التقنية منقّحة من مسارات الخادم |
| NFR-1.8 | مسار التخزين يبدأ بمعرّف الشركة | وعليه تُبنى سياسات التخزين |
| NFR-1.9 | سجل تدقيق | لكل عملية حسّاسة |
| NFR-1.10 | تحديد المعدل | محادثة ٢٠/دقيقة، رفع ١٥/دقيقة، تعديلات ٦٠/دقيقة، زوّار ٦/دقيقة |
| NFR-1.11 | ترويسات أمنية | HSTS، nosniff، منع التأطير، سياسة الإحالة |

**التحقق:** مجموعة اختبارات SQL تُنفَّذ بدور `authenticated` فتخضع لـRLS
كما يخضع لها أي طلب حقيقي — ٥٣/٥٣ ناجحة على PostgreSQL 16 حقيقية. ويُشغَّل معها
**اختبار ضابط (mutation)** يُضعف السياسات عمدًا للتأكد أن الاختبارات
تسقط فعلًا؛ اختبار ينجح في الحالتين لا قيمة له.

## ١٠. خارج النطاق الحالي

**هذا القسم هو أصدق ما في الوثيقة.** ما يلي غير مبنيّ:

| البند | الأثر على البيع |
|---|---|
| **بوابة دفع** | لا يمكن تحصيل الاشتراك تلقائيًا — التحصيل يدوي مؤقتًا |
| **مزوّد بريد (SMTP)** | دعوات الموظفين لا تصل — تُنشأ الحسابات يدويًا مؤقتًا |
