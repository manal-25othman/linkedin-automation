# معرفة AI — Ma3rifah AI

> **حوّل معرفة شركتك إلى ذكاء يعمل معك.**

منصة SaaS متعددة المستأجرين تحوّل مستندات الشركة (سياسات، إجراءات، أدلة) إلى قاعدة معرفة ذكية، يسأل عنها الموظفون بالعربية أو الإنجليزية ويحصلون على إجابات **مبنية على مستندات شركتهم وحدها، مع ذكر المصدر ورقم الصفحة**.

المنصة ليست روبوت محادثة. الفرق الجوهري: عندما لا تكفي المصادر، يقول المساعد ذلك صراحةً بدل التخمين، ويُسجَّل السؤال تلقائيًا في **فجوات المعرفة** ليتحول النقص إلى خطة توثيق قابلة للتنفيذ.

## نظرة معمارية

```
المتصفح (Next.js App Router · RTL)
        │
        ├─ Server Components ──► Supabase (جلسة المستخدم) ──► RLS ──► PostgreSQL
        │                                                              + pgvector
        └─ Server Actions ─────► خدمات التطبيق
                                   ├─ RAG:  استخراج ← تقطيع ← تضمين ← بحث دلالي
                                   ├─ AI:   Claude API لتوليد الإجابة
                                   └─ Admin: عمليات محدودة بمفتاح الخدمة
```

**القرار المعماري المركزي:** عزل المستأجرين مطبَّق في قاعدة البيانات عبر Row Level Security، لا في كود التطبيق. كل استعلام يمر بشرط يقارن `company_id` بشركة المستخدم المستخرجة من `auth.uid()` داخل قاعدة البيانات. حتى لو أخطأ مطوّر ونسي شرط التصفية، لا يستطيع الاستعلام تجاوز حدود الشركة.

دالة البحث الدلالي `match_document_chunks` لا تقبل معرّف شركة من العميل إطلاقًا — تشتقّه بنفسها مع دور المستخدم وقسمه، وتفلتر المقاطع الممنوعة **قبل** حساب التشابه. المقطع الذي لا يملك المستخدم صلاحيته لا يصل إلى النموذج أصلًا.

## إعداد Supabase

1. أنشئ مشروعًا جديدًا على [supabase.com](https://supabase.com) واختر أقرب منطقة جغرافية لمستخدميك.
2. من **Project Settings → API** انسخ:
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role` → `SUPABASE_SERVICE_ROLE_KEY`
3. من **Authentication → Providers** فعّل **Email**.
4. من **Authentication → URL Configuration** اضبط:
   - `Site URL` = رابط تطبيقك
   - `Redirect URLs` = أضف `<رابط التطبيق>/login`
5. للتطوير المحلي: يمكنك تعطيل **Confirm email** من **Authentication → Providers → Email** لتسريع التجربة. **أبقِه مفعّلًا في الإنتاج.**

## إعداد قاعدة البيانات

طبّق ملفات الهجرة **بالترتيب الرقمي**. الطريقة الأسرع عبر لوحة Supabase:

**SQL Editor → New query** ثم الصق محتوى كل ملف ونفّذه بالترتيب:

```
supabase/migrations/
├── 0001_extensions.sql          الامتدادات (pgvector, pg_trgm, unaccent)
├── 0002_core_schema.sql         الشركات، الأقسام، المستخدمون
├── 0003_knowledge_schema.sql    التصنيفات، المستندات، المقاطع والمتجهات
├── 0004_conversations_schema.sql المحادثات، الرسائل، المصادر، فجوات المعرفة
├── 0005_billing_schema.sql      الخطط، الاشتراكات، الاستهلاك، التدقيق
├── 0006_functions.sql           دوال السياق، البحث الدلالي، تسجيل الفجوات
├── 0007_rls_policies.sql        سياسات العزل — لا تتخطَّ هذا الملف
├── 0008_storage.sql             حاويات التخزين وسياساتها
├── 0009_contact_requests.sql    طلبات التواصل من الموقع
├── 0010_analytics_functions.sql دوال التحليلات
└── 0011_seed_support.sql        دالة مساعدة لسكربت العرض (service_role فقط)
```

أو عبر Supabase CLI:

```bash
supabase link --project-ref <project-ref>
supabase db push
```

**اختصار:** بدل تنفيذ الملفات الأحد عشر واحدًا واحدًا، الصقي محتوى `supabase/ALL_MIGRATIONS.sql` كاملًا في SQL Editor ونفّذيه مرة واحدة. يُولَّد بـ`npm run db:bundle` بعد أي تغيير في مجلد الهجرات، وآمن لإعادة التنفيذ.

### التحقق من نجاح التطبيق

## إعداد pgvector والتضمينات

`Claude API لا يوفّر endpoint للتضمينات`، وهي ركن أساسي في RAG. لذلك المشروع يعرّف واجهة `EmbeddingProvider` واحدة خلفها ثلاثة تطبيقات — تبديل المزوّد لاحقًا يعني تغيير متغيّر بيئة وإعادة توليد التضمينات، دون لمس أي كود آخر.

| المزوّد | الاستخدام | ملاحظات |
|---|---|---|
| `voyage` | **الإنتاج** | جودة عالية مع العربية. `voyage-3.5` بأبعاد 1024 |
| `openai` | بديل | أي خدمة متوافقة مع OpenAI Embeddings API |
| `local` | التطوير والاختبار فقط | تجزئة كلمات حتمية — يلتقط التشابه المعجمي فقط، **لا يفهم الترادف** |

### تنبيه مهم بشأن الأبعاد

عمود المتجه معرَّف بـ `vector(1024)` في `0003_knowledge_schema.sql`. إذا غيّرت `EMBEDDINGS_DIMENSIONS` إلى قيمة أخرى، **يجب** تعديل العمود وإعادة توليد كل التضمينات:

```sql
-- مثال: الانتقال إلى 1536 بُعدًا
alter table public.document_chunks alter column embedding type vector(1536);
drop index if exists document_chunks_embedding_idx;
create index document_chunks_embedding_idx on public.document_chunks
  using hnsw (embedding vector_cosine_ops) with (m = 16, ef_construction = 64);
```
ثم عدّل توقيعي `match_document_chunks` و`seed_match_chunks`، وأعد فهرسة كل المستندات من صفحة المستندات.

## إعداد Claude API

1. أنشئ مفتاحًا من [console.anthropic.com](https://console.anthropic.com/settings/keys).
2. ضعه في `ANTHROPIC_API_KEY`.
3. النموذج الافتراضي `claude-opus-5`. لخفض التكلفة على الأحمال العالية يمكن ضبط `ANTHROPIC_MODEL=claude-sonnet-5`.

موجّه النظام (`src/lib/ai/prompts.ts`) يُلزم النموذج بالاعتماد على المصادر المسترجعة فقط، ويوجب التصريح بعدم كفاية المعلومات بصيغة ثابتة تُطابَق نصيًا لتسجيل فجوة المعرفة. **تعديل هذه الصيغة يتطلب تحديث `NO_ANSWER_PATTERNS` في الملف نفسه.**

## البيانات التجريبية

```bash
npm run db:seed              # إنشاء أو تحديث بيانات العرض
npm run db:reset             # حذف كل شيء وإعادة البناء من الصفر
```

ينشئ السكربت شركة **«شركة معرفة للتقنية»** ببيانات وهمية بالكامل:

- 6 مستخدمين بأدوار مختلفة (مدير شركة، مديرا قسم، 3 موظفين)
- 6 أقسام و6 تصنيفات معرفة
- 8 مستندات عربية واقعية **تُفهرس عبر خط المعالجة الحقيقي**: دليل الموظف، سياسة الإجازات، العمل عن بعد، الحضور والانصراف، إجراءات المشتريات، أمن المعلومات، البريد الإلكتروني، ودليل الموظفين الجدد
- 6 فجوات معرفة مفتوحة بعدادات تكرار واقعية
- محادثات مولّدة **باستدعاء حقيقي لـ Claude** إن توفّر المفتاح

بيانات الدخول تُطبع في نهاية التشغيل. كلمة المرور من `DEMO_USER_PASSWORD`.

**جرّب هذه الأسئلة بعد تسجيل الدخول:**

- كم عدد أيام الإجازة السنوية؟
- كيف أطلب إجازة؟
- هل يسمح بالعمل عن بعد؟
- كيف أطلب جهاز كمبيوتر؟
- ما سياسة استخدام البريد الإلكتروني؟
- ماذا أفعل في حال فقدان جهاز الشركة؟

> **كل البيانات التجريبية وهمية.** لا تحتوي على أسماء أشخاص حقيقيين ولا أرقام هوية ولا أي بيانات حساسة، وكل مستند يبدأ بلافتة `[بيانات تجريبية — DEMO DATA]`. هذه السياسات ليست مرجعًا قانونيًا.
>
> **لا يُشغَّل السكربت على قاعدة بيانات إنتاجية** — يعمل بمفتاح الخدمة و`--reset` يحذف بيانات بلا رجعة.

### قائمة تحقق قبل الإطلاق

- [ ] كل ملفات `supabase/migrations` مطبَّقة بالترتيب
- [ ] `select tablename, rowsecurity from pg_tables where schemaname='public'` كلها `true`

- [ ] `EMBEDDINGS_DIMENSIONS` يطابق عمود `vector(N)`

## الاختبارات

```bash
npm run test         # مرة واحدة
npm run test:watch   # وضع المراقبة
```

| الملف | ما يغطيه |
|---|---|
| `tests/unit/chunking.test.ts` | تنظيف النص العربي، كشف نوع الملف، التقطيع، حفظ أرقام الصفحات |
| `tests/unit/rbac.test.ts` | صلاحيات الأدوار الأربعة، وراثتها، كشف الإجابات غير المُجابة، بناء الموجّه |
| `tests/unit/embeddings.test.ts` | حتمية التضمين، التطبيع، تقارب النصوص المتشابهة، تحديد معدل الطلبات |
| `tests/integration/tenant-isolation.test.ts` | **العزل بين الشركات** عبر PostgREST (يتطلب مشروع Supabase) |
| `tests/sql/` | **العزل بين الشركات** على قاعدة PostgreSQL مباشرة (لا يتطلب مفاتيح) |

اختبارات العزل تُنشئ شركتين حقيقيتين وتتحقق أن الشركة «أ» لا تصل إلى بيانات الشركة «ب» عبر: الاستعلام المباشر، تمرير المعرّف صراحةً، البحث الدلالي، التعديل، الحذف، الإدراج، ونقل مستخدم بين الشركتين. كما تتحقق من أن المستخدم لا يستطيع ترقية نفسه إلى مدير منصة.

تتخطّى نفسها تلقائيًا إن لم تتوفر متغيرات Supabase (`NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY` و`SUPABASE_SERVICE_ROLE_KEY`)، لذا **شغّلها مع مشروع Supabase حقيقي قبل كل إصدار**.

### اختبارات العزل على قاعدة بيانات مباشرة (SQL)

الاختبارات السابقة تمر عبر PostgREST وتحتاج مشروع Supabase كاملًا. إلى جانبها توجد حزمة SQL تعمل على أي PostgreSQL بامتداد `pgvector`، فتصلح للتشغيل محليًا وفي CI دون أي مفاتيح:

```bash
# تتطلب PostgreSQL 16 + pgvector، وصلاحية إنشاء قواعد بيانات
PGHOST=localhost PGUSER=postgres npm run test:isolation
```

يبني السكربت قاعدة نظيفة، يطبّق `supabase/migrations` **كما هي**، يزرع شركتين، ثم ينفّذ 42 اختبارًا بدور `authenticated` مع ضبط `request.jwt.claims` — أي بنفس الطريقة التي تُقيَّم بها سياسات RLS في الإنتاج. مع مشروع Supabase حقيقي استخدم `SKIP_SHIM=1` لتخطّي طبقة محاكاة `auth`/`storage`.

| الملف | الدور |
|---|---|
| `tests/sql/00_supabase_shim.sql` | محاكاة `auth.uid()` و`auth.users` و`storage.objects` والأدوار الثلاثة |
| `tests/sql/01_isolation_fixtures.sql` | شركتان، ثلاثة أقسام، خمسة مستخدمين، أربعة مستندات بمستويات ظهور مختلفة |
| `tests/sql/02_isolation_tests.sql` | الاختبارات نفسها (عزل · صلاحيات مستندات · إبطال وصول · تخزين · تصعيد صلاحيات) |
| `tests/sql/90_mutation.sql` | شاهد سلبي: يزرع ثغرة عمدًا |

كل مقاطع المستندات في البيانات التجريبية تحمل **المتجه نفسه**، فتتساوى درجة التشابه تمامًا؛ لو كان في العزل ثغرة لعادت مقاطع الشركة الأخرى حتمًا، ولا يمكن لنتيجة صحيحة أن تكون مصادفة.

```bash
# شاهد سلبي: يعطّل حرّاس العزل ويتوقع فشل الاختبارات
npm run test:isolation:mutate
```

لا يكفي أن تنجح الاختبارات؛ يجب أن تفشل حين تُزرع ثغرة. هذا الأمر يعطّل `belongs_to_current_company` و`can_read_document` وينزع فلاتر الشركة والصلاحيات من `match_document_chunks`، ثم يتحقق أن الحزمة كشفت ذلك.

## الأمان

| الطبقة | التطبيق |
|---|---|
| عزل المستأجرين | RLS على 17 جدولًا؛ الشرط داخل قاعدة البيانات لا في التطبيق |
| صلاحيات المستندات | ثلاثة مستويات (شركة/أقسام/أدوار)، مُطبَّقة داخل دالة البحث قبل حساب التشابه |
| المصادقة | Supabase Auth مع `getUser()` (تحقق من الخادم) لا `getSession()` |
| التفويض | `requirePermission()` على الخادم في كل Server Action |
| مفتاح الخدمة | محصور في وحدات `import 'server-only'`، وكل استخدام مسبوق بتحقق صريح |
| رفع الملفات | تحقق من النوع والحجم والبصمة؛ اسم الملف مطهَّر ضد Path Traversal |
| التخزين | حاوية خاصة؛ مسار كل ملف يبدأ بمعرّف شركته وتحرسه سياسات التخزين؛ التنزيل بروابط موقّعة لمدة دقيقتين |
| تحديد المعدل | نافذة منزلقة لكل مستخدم على الأسئلة والرفع والكتابة |
| حصص الاستخدام | فحص الحد الشهري قبل كل سؤال |
| سجل التدقيق | كل عملية حساسة مع هوية المنفّذ ووقتها |
| التسجيل | تنقيح تلقائي لكلمات المرور والمفاتيح والرموز ومحتوى المستندات |
| رؤوس HTTP | `X-Frame-Options` · `X-Content-Type-Options` · `Referrer-Policy` · `HSTS` |
| رسائل الخطأ | رسائل عربية صالحة للعرض؛ لا stack traces ولا تفاصيل تقنية للمستخدم |

### حدود يجب معرفتها

- **تحديد المعدل في الذاكرة** — يعمل لكل نسخة على حدة. للنشر متعدد النسخ استبدل التخزين في `src/lib/rate-limit.ts` بمخزن مشترك (Upstash Redis أو ما يعادله). الواجهة مصمّمة لهذا الاستبدال دون تغيير مواقع الاستدعاء.
- **`seed_match_chunks`** تقبل معرّف شركة صراحةً، ولذلك صلاحية تنفيذها ممنوحة لـ `service_role` فقط ومسحوبة من `authenticated` و`anon`. **لا تمنحها لأي دور آخر.**

## التحكم في التكلفة

| الإجراء | الأثر |
|---|---|
| حجم المقطع ~1200 محرف مع تداخل 180 | توازن بين دقة الاسترجاع وحجم السياق |
| سقف صارم لعدد المقاطع المسترجعة (≤20) | مفروض داخل دالة قاعدة البيانات لا في التطبيق |
| سقف رموز للسياق (6000) | يمنع انفجار حجم الطلب مهما كثرت المقاطع |
| نافذة تاريخ محادثة محدودة | افتراضيًا 6 رسائل، قابلة للضبط من الإعدادات |
| تخزين مؤقت لموجّه النظام | الموجّه ثابت لكل أسئلة الشركة الواحدة — أكبر جزء قابل للتخزين المؤقت |
| نموذج أصغر لتوليد العناوين | `claude-haiku-4-5` بسقف 40 رمزًا |
| `effort` قابل للضبط | من متغير بيئة واحد |
| حصص شهرية لكل خطة | تمنع التكاليف غير المتوقعة |

كل استدعاء يُسجَّل في `ai_usage_logs` بعدد رموز الدخل والخرج والتكلفة التقديرية والزمن، ويُجمَّع شهريًا في `usage_records`. مدير الشركة يرى الاستهلاك في الإعدادات، ومدير المنصة يرى التكلفة الإجمالية في `/admin`.

**التحكم الأهم متاح لمدير الشركة نفسه** من صفحة الإعدادات: عدد المقاطع المسترجعة، وعدد المقاطع المُرسلة للنموذج، وحد التشابه الأدنى — ثلاثة عوامل تحدد جودة الإجابة وتكلفتها معًا.

## قيود معروفة

| القيد | التفصيل |
|---|---|
| **المستندات الممسوحة ضوئيًا** | ملفات PDF المكوّنة من صور تحتاج معالجة OCR قبل الرفع. النظام يكشف الحالة ويعرض رسالة واضحة بدل الفشل الصامت. |
| **المزوّد المحلي للتضمينات** | يلتقط التشابه المعجمي فقط ولا يفهم الترادف. للتطوير والعرض حصريًا. |
| **بوابة الدفع** | غير مربوطة. البنية جاهزة: `plans` و`subscriptions` و`usage_records` مع `limit_overrides`، وحقول `external_customer_id` و`external_subscription_id` بانتظار الربط. |
| **دعوة المستخدمين** | تعتمد على إعداد البريد في Supabase. بدونه تفشل الدعوة برسالة واضحة. |
| **معالجة المستندات** | تعمل داخل عملية الخادم. للملفات الكبيرة جدًا أو الأحجام العالية، انقلها إلى طابور خلفي (Supabase Edge Function أو ما يعادله) — `ingestDocument` مكتوبة كدالة مستقلة تسهّل هذا النقل. |
| **الواجهة الإنجليزية** | البنية جاهزة (كل النصوص في مكوّنات، لا سلاسل مبعثرة في المنطق) لكن ملفات الترجمة لم تُنشأ بعد. |
