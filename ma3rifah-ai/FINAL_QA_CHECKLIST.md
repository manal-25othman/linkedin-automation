## 2. هل نُفِّذت الاختبارات ضد قاعدة بيانات حقيقية؟

**نعم — قاعدة PostgreSQL حقيقية تعمل فعليًا، لا محاكاة ولا Mocks.**

| البند | القيمة |
|---|---|
| المحرّك | PostgreSQL 16.13 (عملية حقيقية) |
| الامتدادات | `vector 0.6.0` · `pg_trgm 1.6` · `pgcrypto 1.3` · `unaccent 1.1` · `uuid-ossp 1.1` |
| المخطط | ملفات `supabase/migrations/*.sql` الأحد عشر مطبَّقة **كما هي، بلا تعديل** |
| دور التنفيذ | `authenticated` مع `set local request.jwt.claims = '{"sub": …}'` |

**ما هو حقيقي:** كل سياسات RLS، وكل دوال `security definer`، و`auth.uid()`، وفهارس pgvector، وحسابات التشابه — كلها تعمل داخل محرّك PostgreSQL فعلي.

**ما هو محاكى:** ثلاث واجهات فقط تعتمد عليها الهجرات ولا يوفّرها PostgreSQL العادي — `auth.users`، ودالة `auth.uid()` (تقرأ `request.jwt.claims` تمامًا كتطبيق Supabase)، وجدولا `storage.objects`/`storage.buckets`. **لم تُعدَّل أي سياسة أو دالة من دوال المنتج.**

**ما لا تغطيه هذه الحزمة:** بوابة PostgREST نفسها، والتحقق من توقيع الـJWT، وسياسات Supabase Auth. لذلك تشغيل `tests/integration/tenant-isolation.test.ts` على مشروع Supabase حقيقي **يبقى شرطًا قبل الإطلاق** (انظر القسم 6).

### 3.3 منع استرجاع مستندات شركة أخرى عبر RAG ✅

| من يسأل | مقاطع في السياق | من الشركة ب |
|---|---|---|
| مدير الشركة أ | 3 | **0** |
| موظف المالية (شركة أ) | 1 | **0** |
| مدير الموارد البشرية (شركة أ) | 2 | **0** |
| حساب معطّل | — | ❌ `unauthorized: no active company profile for current user` |

**الآلية:** `match_document_chunks` دالة `security definer` **لا تقبل معرّف شركة من العميل إطلاقًا** — تشتق الشركة والدور والقسم من `auth.uid()` داخل قاعدة البيانات، وتطبّق شروط الصلاحية في جملة `where` **قبل** ترتيب التشابه. حتى لو أخطأ كود التطبيق فلا سبيل لتمرير معرّف شركة أخرى.

**على مستوى التطبيق:** `retrieveRelevantChunks()` في `src/lib/rag/retrieval.ts` تستقبل **عميل جلسة المستخدم** لا عميل مفتاح الخدمة. استخدام `createAdminClient()` محصور في مسار الاستيعاب (`ingest.ts`) وتسجيل الاستهلاك (`chat-service.ts`) — ولا يمرّ منه أي محتوى مستند إلى النموذج.

**نقطة تصميم:** كل مقاطع البيانات التجريبية تحمل **المتجه نفسه**، فدرجة التشابه متساوية تمامًا بين الشركتين. لو كان في العزل ثغرة لعادت مقاطع الشركة الأخرى حتمًا — لا مجال لنتيجة صحيحة بالمصادفة أو بأثر الترتيب.

## 6. ما يحتاج إعدادًا منكِ

### 6.1 Supabase — مطلوب

1. أنشئي مشروعًا على [supabase.com](https://supabase.com) واختاري منطقة قريبة (Frankfurt أو Singapore).
2. **Project Settings → API** — انسخي:
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role` → `SUPABASE_SERVICE_ROLE_KEY` ⚠️ **لا يُعرض في المتصفح ولا يُوضع في Git**
3. **SQL Editor** — نفّذي ملفات `supabase/migrations/*.sql` **بالترتيب الرقمي** من `0001` إلى `0011`.
4. **Storage** — تُنشئ الهجرة `0008` الحاويات تلقائيًا. تأكدي أن حاوية `documents` **خاصة (Private)** لا عامة.
5. **Authentication → Providers → Email** — فعّلي البريد. للتجربة السريعة أوقفي «Confirm email»، وأعيدي تفعيله قبل الإنتاج.
6. **Authentication → URL Configuration** — أضيفي `Site URL` ونطاق Vercel في `Redirect URLs`.
7. **Authentication → SMTP** *(مطلوب للدعوات)* — اربطي مزوّد بريد (Resend أو SendGrid). بدونه تفشل دعوة المستخدمين.

### 6.2 Claude API (Anthropic) — مطلوب

1. مفتاح من [console.anthropic.com/settings/keys](https://console.anthropic.com/settings/keys) → `ANTHROPIC_API_KEY`.
2. **Billing** — اشحني رصيدًا؛ بدونه ترتد كل الطلبات.
3. اختياريًا اضبطي `ANTHROPIC_MODEL` (افتراضيًا `claude-opus-5`) و`ANTHROPIC_EFFORT` (`medium`) و`ANTHROPIC_MAX_OUTPUT_TOKENS` (`2000`).
4. **موصى به:** ضعي حدًا شهريًا للإنفاق في **Limits** كسقف أمان فوق حصص المنصة الداخلية.

### 6.3 Voyage AI (التضمينات) — مطلوب للإنتاج

Claude API **لا يوفّر endpoint للتضمينات**، لذا يلزم مزوّد منفصل.

1. مفتاح من [dash.voyageai.com](https://dash.voyageai.com) → `VOYAGE_API_KEY`.
2. `EMBEDDINGS_PROVIDER=voyage` و`VOYAGE_MODEL=voyage-3.5` و`EMBEDDINGS_DIMENSIONS=1024`.
3. ⚠️ **الأبعاد يجب أن تطابق العمود `vector(1024)` في قاعدة البيانات.** لو غيّرتِ النموذج إلى أبعاد مختلفة، عدّلي الهجرة **وأعيدي توليد كل المتجهات** — لا يكفي تغيير المتغيّر.
4. بديل: أي مزوّد متوافق مع OpenAI Embeddings (`EMBEDDINGS_PROVIDER=openai` + `OPENAI_API_KEY`).
5. `EMBEDDINGS_PROVIDER=local` للتطوير بلا مفاتيح فقط — **لا يصلح للإنتاج**.

### 6.4 Vercel — مطلوب للنشر

1. اربطي المستودع، واضبطي **Root Directory = `ma3rifah-ai`** (المشروع في مجلد فرعي).
2. أضيفي كل متغيرات `.env.example` في **Settings → Environment Variables** لبيئات Production وPreview وDevelopment.
3. `NEXT_PUBLIC_APP_URL` = نطاق Vercel الفعلي (لا `localhost`).
4. `INTERNAL_API_SECRET` — ولّديه بـ`openssl rand -base64 32`.
5. بعد أول نشر أعيدي `NEXT_PUBLIC_APP_URL` و`Redirect URLs` في Supabase إلى النطاق النهائي.

### حسابات البيانات التجريبية

بعد `npm run db:seed` تُنشأ شركة **«شركة معرفة للتقنية»** بثمانية مستندات وأربعة مستخدمين بأدوار مختلفة. كلمة المرور الموحّدة من `DEMO_USER_PASSWORD` في `.env.local`. تُطبع الحسابات في مخرجات السكربت. جميع البيانات مُعلَّمة `[بيانات تجريبية — DEMO DATA]` ولا تحتوي أي بيان شخصي حقيقي.

**ملاحظة:** يشغّل السكربت مسار الاستيعاب الحقيقي (استخراج → تقطيع → تضمين). إن لم يوجد مفتاح Claude فلن يُلفّق إجابات ذكاء اصطناعي — يتخطّى تلك الخطوة ويخبرك بذلك.
